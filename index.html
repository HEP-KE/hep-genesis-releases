An agent for scientific computing, on your laptop or on HPC.

HEP-Genesis-Agent is a desktop and command-line client. A chat agent calls tools on MCP servers and runs compute either on your machine or on DOE facilities (ALCF Polaris, NERSC Perlmutter) through IRI and Globus.

Overview

What it does

One client for model endpoints, MCP tool servers, and facility compute. The desktop app and the CLI share the same backend, projects, skills, and memory.

Two chat modes

Quick: one agent calls tools directly. Research: a lead agent writes a plan, a worker runs it step by step, and the run ends in a written report. The app shows a live graph of the running agent.

MCP servers

Connect stdio and streamable-HTTP servers, including hosted HEP-KE servers and their OAuth sign-in. Each server shows its tool list and logs.

Local or HPC

A target picker sends the same tool call to your machine, to Polaris (PBS), or to Perlmutter (Slurm). Staging goes over Globus Transfer, and job results come back to your laptop.

Figures and reports

Plots from tools appear inline as numbered figures with captions, and CSV files open as tables. Research reports are set like a preprint, and you can export them to PDF with all figures embedded.

Any OpenAI-compatible model

Enter a base URL, a key, and a model name, plus extra headers if your lab gateway needs them. Presets cover common providers and ALCF's inference gateway. The app encrypts keys with the OS keychain.

Projects and provenance

Each project directory collects run outputs, dispatched-job artifacts, resume state, and provenance. You can link existing codebases so optional coding tasks can build on them.

Option 1 · app only

Chat and hosted tools

Most users only need the app. You don't need Python for:

  • chat with Quick and Research runs, plus reports and PDF export
  • hosted MCP servers and their OAuth sign-in
  • projects, skills, and memory
  • coding tasks, since the harness ships inside the DMG
Option 2 · app + backend

Local science servers and HPC dispatch

Install the wheel as well if you need:

  • bundled stdio MCP servers (hep-genesis-domain and the facility servers)
  • facility sign-in, job tracking, and Polaris or Perlmutter dispatch
  • the headless hep-genesis-agent CLI

HPC dispatch also requires a facility account with an allocation and Globus Connect Personal.

macOS app

Open the DMG and drag the app into /Applications. Alpha builds are not signed yet, so macOS may report that the app “is damaged and can't be opened”. The app isn't damaged: macOS shows this message for any unsigned app downloaded in a browser. Run this command once, then open the app normally:

$ xattr -dr com.apple.quarantine "/Applications/HEP-Genesis-Agent.app"

Python backend

Install the wheel into a dedicated Python ≥ 3.10 environment. The [all] extra adds the agent, service, and HPC dependencies. Replace the filename with the one you downloaded.

$ conda create -n hep-genesis python=3.12 -y
$ conda activate hep-genesis
$ pip install 'hep_genesis-<version>-py3-none-any.whl[all]'

When the app starts for the first time, it looks for conda environments that contain the backend. If it doesn't find yours, choose HPC → Pick python and select that environment's python.

Using the app

The desktop app

Each area of the app has its own tab in the navigation rail. On first launch, follow the steps below in order. After that, you'll mostly use Chat.

Add a model endpoint

Models: choose a preset or enter your gateway's base URL, API key, and model name. ALCF-FIRST only needs a Globus login.

Connect servers

Servers: the hosted servers connect automatically. Add hep-genesis-domain for local science tools, or any other stdio or HTTP MCP server.

Start the backend (optional)

HPC: choose the Python environment, start the backend, and sign in to ALCF or NERSC. Globus Connect Personal must be running.

Chat

Choose Quick or Research in the composer, and choose where compute runs: On this machine, Polaris, or Perlmutter.

Research sources. Web search, multi-source paper search (arXiv, Semantic Scholar, OpenAlex, Crossref), and arXiv figure extraction can each be turned on or off. The app applies the website policy (academic-only, custom list, or open) to every page fetch. The search tools run through uvx, so they need uv installed.
Headless

Command line

You can use every feature without the desktop app. The wheel installs the CLI agent, the backend service, the MCP servers, and the facility sign-in commands. They share the same projects under ~/hep-genesis/.

Set the model endpoint with environment variables. Any OpenAI-compatible API works. You can also set a different model for each stage with LLM_PLANNER_*, LLM_WORKER_*, and LLM_SYNTHESIS_*.

$ export LLM_URL=https://your-gateway/v1
$ export LLM_MODEL=your-model
$ export LLM_API_KEY=...

Pass a question, a project, and one or more MCP servers. The project is created if it doesn't exist. When the run finishes, the report is printed and the outputs stay in the project directory.

$ hep-genesis-agent "compute a test power spectrum" \
    --project qcd-eos \
    --servers module:hep_genesis.domain.mcp_server \
    --servers "command:uvx duckduckgo-mcp-server"
Server specs. module:<python.module> runs an installed module. command:<exe args…> runs an executable. A local path or a git URL is pip-installed first and then run. You can repeat --servers.

Projects live in ~/hep-genesis/projects, or in HEP_PROJECTS_DIR if you set it. Use --resume to pick up an interrupted run of the same query.

$ hep-genesis-agent --list-projects
$ hep-genesis-agent "…same query…" --project qcd-eos --resume

To let the agent write and run code, link a codebase and add --coding. You approve each coding task at a prompt, and all code is saved under the project. A local folder is linked in place. A git URL is cloned at a fixed commit.

$ hep-genesis-agent --project qcd-eos \
    --link-codebase ~/code/my-analysis
$ hep-genesis-agent "fit the slope of the downloaded HMF" \
    --project qcd-eos --coding \
    --servers module:hep_genesis.domain.mcp_server

Each facility needs two sign-ins: one for the IRI API (jobs) and one for Globus Transfer (data). Each command prints a Globus URL and asks you to paste back the code. Tokens are stored in ~/.globus/ and refresh automatically.

# ALCF (Polaris)
$ hep-genesis-alcf-auth
$ hep-genesis-alcf-transfer-auth
# NERSC (Perlmutter)
$ hep-genesis-nersc-auth
$ hep-genesis-nersc-transfer-auth

Facility sessions expire under each site's policy. For example, ALCF MFA lasts about 24 hours. When a session expires, dispatch reports the exact re-auth command to run. The desktop HPC panel uses the same flows and tokens.

# ALCF inference gateway (ALCF-FIRST model endpoint)
$ hep-genesis-alcf-inference-auth

Facility compute

How a dispatched run works

When the target is Polaris or Perlmutter, the agent calls the same MCP tool it would call locally. The backend's set_dispatch tool sends the call through the steps below. Jobs keep running if you quit the app, and the backend picks up polling again when it restarts.

Stage

Inputs go to the facility over Globus Transfer. NERSC can also stage through the IRI filesystem API.

Submit

The job is submitted through the facility's IRI API to PBS on Polaris or Slurm on Perlmutter.

Poll

The backend tracks job state. The Jobs list shows live logs.

Read back

Logs and results are read over IRI, so an expired Globus session can't hide a failure.

Results

Datasets are registered with the tool server, and artifacts are copied into your project.

Dispatch has been tested end to end on Polaris and Perlmutter. Other DOE facilities are not supported yet.
